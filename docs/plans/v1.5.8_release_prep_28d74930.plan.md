## Phase 4b - Fix bundle "Health Check Results: MISSING"

Root cause: under QP-2 segmentation the bundler scans the per-cluster `clusters/<key>/output/health/` (`cp.health`), but the report-phase health save writes to the flat `<data_dir>/output/health/`, so the file is never found. Confirmed against [import/Assets-2026-06-25/SUMMARY.md](import/Assets-2026-06-25/SUMMARY.md) line 11.

- In [src/oneshot_runner.py](src/oneshot_runner.py) (embedded save ~line 1682, and standalone `_run_health_checks` ~lines 1364-1366): write to `str(self._cluster_paths.output)` when `self._cluster_paths is not None`, else the flat `get_data_dir()/output`. Apply to both `save_json` and `generate_remediation_report` so `health_check_*.json` and `health_remediation_*.txt` land in `cp.health` and are picked up by the bundler.
- Make SUMMARY status truthful: pass a `health_check` entry into the bundler's `operation_status` in `_run_bundle` - `success` when health ran, `skipped` when `_include_health` is false - so [src/result_bundler.py](src/result_bundler.py) `_compute_category_status` reports OK/SKIPPED instead of MISSING.
- Verify by running a one-shot with health enabled and confirming SUMMARY shows `Health Check Results: OK (from this run)`; and with health disabled, `SKIPPED`.
