Quick Start Guide

Download, install, and launch the application on macOS or Windows in minutes — then follow the field procedure to run, collect, and post results for every deployment.

Jump to the Field Procedure ↓

macOS Installation

Choose your path below. New installs and upgrades share most steps, but upgrades require exiting the running app and replacing the existing copy first.

Upgrade Only
Step

Download the Update from the App

The app checks for new releases at launch. Look at the version pill beside the asbuilt-reporter name in the header:

  • LATEST VERSION — you are already current; no upgrade needed.
  • UPDATE AVAILABLE — a newer release exists, and a Download button appears next to the pill.

Click the caret beside Download to open the dropdown. It shows the new version number, the version you are running, and a Release notes link. Choose the download for your platform and wait for it to finish before moving on.

Running 1.6.1 or later? The dropdown lists macOS — Apple Silicon and macOS — Intel separately, plus an Exit & Upgrade button that performs the next step for you. Earlier versions offer a single macOS download, as shown here.
No pill at all? The app could not reach GitHub — common on customer sites. Download from the releases page instead and compare against the version shown in the header.
Upgrade Only
Step

Exit the Running Application

macOS refuses to replace an app that is still running, so this step is not optional — skipping it is the most common cause of a failed upgrade. In the app's navbar, click the Exit button (top-right corner).

Wait until the page reports that the application has stopped before continuing.

Closing the browser tab is not enough — the local server keeps running. Use Exit, or Exit & Upgrade in the Download dropdown on 1.6.1 and later.
If the app doesn't quit cleanly, open Activity Monitor and force-quit any "VAST Reporter" processes.
All Installs
Step

Open the DMG and Install

Download the DMG that matches your Mac from GitHub Releases, then double-click it to mount:

  • Apple Silicon (M1/M2/M3/M4) — VAST-Reporter-vX.Y.Z-mac-arm64.dmg
  • Intel — VAST-Reporter-vX.Y.Z-mac-x64.dmg
Not sure which you have? Apple menu → About This Mac. A "Chip" line (e.g. Apple M2) means Apple Silicon; a "Processor" line means Intel.

Double-click the DMG you downloaded earlier — it is in your Downloads folder unless you chose another location — to mount it.

Drag VAST Reporter.app onto the Applications folder shortcut to install.

Upgrade Only
Step

Replace the Existing Version

Since an earlier version is already installed, macOS will ask if you want to replace it. Click Replace to overwrite the old version with the new one.

"Keep Both" will create a duplicate with a different name — always choose Replace for a clean upgrade.
All Installs
Step

Gatekeeper Warning — Click Done

On first launch, macOS Gatekeeper will block the app because it is not signed with an Apple Developer certificate. You'll see a dialog saying "VAST Reporter.app" Not Opened.

This is expected for internal tools distributed outside the App Store. Click Done — do not click "Move to Trash".

All Installs
Step

Open System Settings → Privacy & Security

Open System Settings (Apple menu → System Settings) and navigate to Privacy & Security in the left sidebar.

Scroll down to the Security section. You'll see a message: "VAST Reporter.app" was blocked to protect your Mac.

Click the Open Anyway button next to the message.

All Installs
Step

Confirm — Open Anyway

A second confirmation dialog will appear asking if you really want to open the app. macOS includes a warning about unverified software.

Click Open Anyway to proceed. Do not click "Move to Trash" or "Done".

All Installs
Step

Authenticate with Touch ID or Password

macOS requires administrator authorization to allow the unsigned app to run. Use Touch ID or click Use Password... and enter your Mac administrator password.

After authenticating, the app will launch and your browser will open automatically to localhost:5173.

You only need to complete the Gatekeeper steps once per version. Subsequent launches will open normally.

Windows Installation

The Windows build is distributed as a portable ZIP archive — no installer required. Extract, run, and go.

1

Download the ZIP

Download VAST-Reporter-vX.Y.Z-win.zip from GitHub Releases.

2

Extract the Archive

Right-click the ZIP file and select Extract All... Choose a destination folder (e.g., C:\Program Files\VAST Reporter or your Desktop).

3

Run the Application

Open the extracted folder and double-click vast-reporter.exe to launch.

4

SmartScreen Warning

On first launch, Windows SmartScreen may display a warning: "Windows protected your PC." This is expected for unsigned internal tools.

Click More info, then click Run anyway to proceed.

5

Application Launches

Your default browser will open automatically to localhost:5173. The app is ready to use.

To upgrade, close the running app, replace the extracted folder with the new version, and relaunch. The SmartScreen step will repeat for each new version.

After Installation: Deployment Tools

The validation workflows do not ship inside the app. They are fetched separately and cached locally, so a fresh install — and every upgrade — is worth a quick check before you rely on them in the field.

All Installs

Check and Update from the Header

Click Update Tools in the top-right of the header. The dropdown lists every tool with its description, cached size, and the date it was last updated. The heading shows how many are cached — 4/4 cached means you are ready to run.

Tools older than a week carry an age badge such as 12D OLD. That is a prompt, not an error: a cached tool keeps working, but validation results are only as current as the tool that produced them.

Click Update Tools at the bottom of the dropdown to fetch the latest versions. Progress appears in the Output Results terminal on the Reporter page.

This needs outbound network access. On an air-gapped customer site, update the tools before you travel — the cached copies are what you will be running on.
Earlier versions also carried Update Tools and Tool Status buttons on the Reporter page. From 1.6.1 the header dropdown is the single place this lives.

Field Procedure: As-Built Report & Post-Deployment Test Suite

Expected of every PSE and SE on every deployment: run the as-built report and the full Test Suite, confirm the results, and post them to the customer's SFDC account and internal Slack channel.

Before you go — needs internet
Step 1

Download and Install the Current Release

Install the latest release — macOS .dmg or Windows .zip — from GitHub Releases. The installation steps above walk through Gatekeeper and SmartScreen.

Already installed? Check the version pill in the app header. UPDATE AVAILABLE means follow the Upgrade from Earlier Version path above; LATEST VERSION means you are current.

Customer sites often block GitHub, so the pill may not appear there. Update before you travel.
Step 2

Launch the App and Open the Local UI

Open VAST Reporter. Your browser opens the UI at localhost:5173 automatically. Everything runs on your laptop — nothing is hosted remotely.

If port 5173 is already in use, the app picks the next free port (5174–5180). Use whatever address the browser opened.
To stop the app, click Exit in the header. Closing the browser tab leaves the local server running.
Step 3

Run Update Tools

Click Update Tools in the top-right of the header, then click the Update Tools button at the bottom of the dropdown. This fetches the latest vnetmap.py, mlnx_switch_api.py, vast_support_tools.py, and vperfsanity package.

You are ready when the dropdown heading reads 4/4 cached. Age badges such as 13D OLD are a prompt to refresh, not an error.

Needs internet. The tools download from VAST's public storage. On an air-gapped or restricted customer network, run this before you arrive — the Test Suite uses the cached copies. See Deployment Tools above for details.
On site — connect and run
Step 4

Open the Reporter Page

Click Reporter in the header to open Reporter & One-Shot Test Suite. Every remaining on-site step happens on this page: Connection Settings at the top, and the Reporter / Test Suite tabs with the Select Operation tile below.

Before connecting, confirm the VMS prerequisites for Step 7 with the installer: racks created, U-heights assigned, and switches added in VMS.
Step 5

Connect Your Laptop to the Cluster

Pick the connection mode that matches how your laptop reaches the cluster. You select the mode in Step 6.

ModeIP to enterUse when
Tech Port192.168.2.2Your laptop is cabled directly to a CNode tech port.
VMS MgmtVMS management VIPYour laptop is on the customer management network or VPN.
Teleport (Beta)VMS management VIP (not 127.0.0.1)Remote access. Requires the tsh client (the pill reads tsh Installed) and an active tsh login session. Also fill in the Teleport Node and User fields that appear.
Step 6

Select or Create a Cluster Profile

Choose the cluster under Saved Profiles, or click ⊕ to create a new one. Then:

  1. Enter the Tech Port IP / VMS VIP from Step 5.
  2. Check the credentials. Usernames default to support (VMS), vastdata (node), and cumulus (switch).
  3. Leave Autofill Passwords on to use the standard factory defaults. If the customer has changed any password, turn it off and type the passwords in.
  4. Select the connection mode — Tech Port, VMS Mgmt, or Teleport.
  5. Click Save.
You can create the profile before arriving on site to save time.
Saved profiles store passwords in plain text on your laptop. See Handling customer data.
Step 7

Run Discovery and Assign Switch U-Heights

This places switches in the rack diagram so it matches the physical install.

  1. Click Discovery in the step bar at the bottom of the Select Operation tile to open the Switch Placement Editor.
  2. Click Run Discovery. The editor reports how many racks and switches it found.
  3. For each row, confirm the Rack and Switch, and set the Height (U position).
  4. Click + Switch to add any switch VMS doesn't know about, such as customer-managed switches.
  5. Click Save to Profile. The tile then shows the rack and switch counts, for example 1 Racks · 2 Switches Placed.
Prerequisites in VMS. The rack must exist with a U-height assigned to every CBox, DBox, and EBox, and the switches must be added to VMS. Unplaced chassis can't be drawn, so the rack diagram will be empty or partial no matter what you set here.
Step 8

Select the Test Suite Tab

Click Test Suite in the Reporter / Test Suite toggle above the Select Operation tile. The tile switches from the report-only options to the full list of post-deployment operations, described in Step 9.

The rack and switch counts from Step 7 carry over to this tab, so there's no need to run Discovery again.
Step 9

Select All Operations and Click Run

Check every operation, including Include Health Checks (Tier 1 & 3):

OperationWhat it doesTime / impact
Re-ValidationPre-flight check of credentials, VMS access, rack and switch config, and SSH access.Seconds
VAST vnetmapLLDP topology validation to catch mis-cabling.Minutes; read-only
VAST Support ToolsRuns vast_support_tools diagnostics and downloads the archive.Several minutes
VAST vperfsanityCreates test views, runs write/read performance tests, uploads results to VAST, and cleans up.30+ min; real I/O load
VMS Log BundleCreates and downloads a VMS log archive.Depends on log size
Switch ExtractionSaves the running config of each discovered switch.Minutes; read-only
Network ExtractionCollects node network config, interfaces, routes, and bonds.Minutes; read-only
Generate As-Built ReportBuilds the PDF and JSON. Include Health Checks adds the Tier 1 & 3 checks.A few minutes

Confirm the vperfsanity VIP Pool name (default main), then click Run.

Progress streams to the Output Results pane. Re-Validation runs first; if it reports a problem, fix it and click Run again. Use Cancel to stop a run.

vperfsanity puts real load on the cluster. Run it before customer data or workloads land, or get the customer's OK first.
A full run commonly takes an hour or more. Keep the laptop awake, plugged in, and connected until it finishes.
After the run — collect and review
Step 10

Download the Results Bundle

Click Results in the header, open the Bundles tab, and find the newest validation_bundle_<cluster>_<YYYYMMDD_HHMMSS>.zip for your cluster (newest at the top). Click the download icon under Actions.

The bundle contains every Test Suite output, plus the as-built PDF and JSON under reports/.

Use Cluster Filter to narrow the list when your laptop holds results from several clusters.
Step 11

Confirm All Tests Completed

Unzip the bundle and open SUMMARY.md. Under Category Status, every category should read OK. (manifest.json holds the same status in machine-readable form.)

StatusMeaningWhat to do
OKOutput collected from this run.Nothing.
SKIPPEDThe operation wasn't selected.Rerun it — this procedure expects every operation.
FAILEDThe operation ran but produced no output.Check the Output Results pane, fix the cause, and rerun that operation.
STALEOnly a file from before this run was found. It is excluded, or included as PRIOR with a banner.Rerun that operation.
MISSINGNo output file was found.Rerun that operation.
If you rerun an operation, post the new bundle alongside the first one, and note any category that still isn't OK in your Slack post (Step 13).
Step 12

Review Port Mapping and vnetmap for Mis-Cabling

Check the cabling results in two places:

  • As-built PDF — the Port Mapping section shows which switch port connects to which node, and the Logical Network Diagram carries a banner. Green PASS means clean; a red "Cabling validation: N mis-cabled switch(es) detected" banner and red dashed outlines mark problem switches.
  • vnetmap output — in the bundle or on Results → vnetmap. A clean run reports "No cross-connections detected. All cabling is correct."; otherwise it lists each cross-connection.
Fix any mis-cabling with the installer, then rerun vnetmap and the as-built report so the posted results reflect the final cabling.
Post results
Step 13

Attach Results to SFDC and Slack

Attach these three files in both places:

  • The as-built report PDF
  • The as-built report JSON
  • The results bundle .zip from Step 10

SFDC: the customer account → Notes & Attachments.
Slack: a thread in #internal-<customer-name>. You can copy this template:

As-Built Report + Post-Deployment Test Suite results: <cluster name> (<PSNT>)
- Reporter version: v<x.y.z>
- Run date: <YYYY-MM-DD>
- Test Suite: all categories OK  |  Exceptions: <category, status, reason>
- Cabling: no mis-cabling found  |  Issues: <switch/port, remediation>
- Also attached to the SFDC account under Notes & Attachments
Files: <report>.pdf, <report>.json, validation_bundle_<cluster>_<timestamp>.zip
The bundle already contains the PDF and JSON. Attach them separately anyway so they open without unzipping.
Reference

Where your files are

Results are saved next to the app, in the clusters/, reports/, and output/ folders. The Results page is the easiest way to find and download them.

  • macOS: the folder containing VAST Reporter.app — usually /Applications.
  • Windows: the folder you extracted the ZIP into.

Windows upgrades: copy those folders and config/ out before replacing the extracted folder, or your results and profiles go with it.

Handling customer data

  • Reports and bundles contain customer configuration — IPs, hostnames, and switch configs. Share them only in internal channels and on the customer's SFDC account.
  • Saved profiles keep passwords in plain text in config/cluster_profiles.json on your laptop. Don't share that folder, and delete profiles you no longer need.

Troubleshooting

SymptomLikely cause and fix
"Unable to reach <ip>… timed out"Wrong IP for the selected mode, or no link. Check the cable or VPN, and that the mode matches the IP (Step 5).
"Authentication failed"The customer changed a default password. Turn off Autofill Passwords and enter the real credentials (Step 6).
Empty rack diagram / "No switches were discovered"VMS prerequisites missing. Assign rack U-heights and add switches in VMS, or add switches with + Switch (Step 7).
Update Tools failsNo internet access. Previously cached tools still work; update again from a connected network (Step 3).
A category isn't OK in SUMMARY.mdSee the status table in Step 11. Scroll back through the Output Results pane for the operation's error.
Browser doesn't open, or the page won't loadCheck the address the app opened (5173–5180). Click Exit, or quit the app, and relaunch.
